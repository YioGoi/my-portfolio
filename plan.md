# Senior frontend portfolio refactor

## Goal

Position the site around senior frontend engineering for Spain-based and Spain-eligible opportunities while preserving the existing typography, geometric visual language, colour direction, and responsive character.

## Verified baseline

- Next.js App Router project on Next.js 16.0.8, React 19.2.1, and TypeScript 5.
- npm is the package manager; `package-lock.json` is present (lockfile v2).
- Existing routes: Home, About, Experience, Skills, Education, Projects, Blog, Contact, and Not Found.
- Existing project links point to public GitHub repositories; Atlas and Signal Ops are available as adjacent local repositories with architecture, testing, and performance evidence.
- No static CV PDF exists in `public/`; the current CV is generated by `@react-pdf/renderer`.
- `components/ResumePDF/index.tsx` contains a pre-existing uncommitted location correction and will not be overwritten.
- The existing `next lint` script is incompatible with Next.js 16; the baseline production build starts successfully, but the baseline lint command fails before linting files.
- No automated test script or CI workflow currently exists.

## Implementation

- [x] Audit repository structure, git status, package manager, framework version, routes, components, scripts, links, and CV assets.
- [x] Centralize verified profile, flagship project, supporting project, leadership, and writing content.
- [x] Refocus the homepage hierarchy: positioning, Atlas, Signal Ops, production foundations, selected writing, contact.
- [x] Rework Projects into decision-and-trade-off case studies with explicitly scoped local evidence.
- [x] Tighten About, Skills, Writing, Contact, navigation, and metadata around senior frontend positioning.
- [x] Improve semantic structure, keyboard access, reduced-motion behavior, focus states, and responsive layouts.
- [x] Add deploy-readiness safeguards: corrected lint/typecheck/test scripts, content policy tests, CI, sitemap, robots, and repository documentation.
- [x] Run lint, tests, type checking, and a production build; inspect final git diff without touching unrelated changes.

## Verification result

- `npm run check` passes: ESLint, TypeScript, four content-policy tests, and the webpack production build.
- All 13 application routes prerender as static content.
- Production-mode HTTP smoke checks return 200 for the core pages, robots, and sitemap.
- The rendered homepage is location-neutral; Contact contains only the approved relocation statement.
- The dependency review was completed without `npm audit fix`: Next.js and its ESLint config were explicitly updated from 16.0.8 to 16.3.4, Sass from 1.87.0 to 1.103.1, and ESLint from 9.21.0 to 9.39.5. Vulnerable transitive resolutions were patched within their existing parent ranges.
- A clean `npm ci` is reproducible and the final full `npm audit` reports zero vulnerabilities.

## Content guardrails

- Homepage stays location-neutral.
- Contact uses: “Based in Istanbul, Türkiye · Relocating to Spain”.
- No Spain work-authorisation or sponsorship claim.
- No Arnhem or Amsterdam as a current personal location.
- Signal Ops is described only as ordered/resumable Server-Sent Events (SSE), never WebSockets.
- Measurements include their date/environment limitations and are not presented as hosted production results.
- No new live-demo links, responsibilities, outcomes, team sizes, or business metrics without repository evidence.
